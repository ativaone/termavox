Seus terminais, ancorados.

Feche o navegador, volte de qualquer lugar e continue exatamente de onde parou. O Termdock é um runtime auto-hospedado que mantém suas sessões SSH abertas num servidor que você controla; o navegador é só uma janela para elas.

A vida do navegador não é a vida do terminal.

Na maioria das ferramentas de SSH pela web, a aba do navegador é a sessão: fechou o notebook ou caiu o Wi-Fi, a conexão morre junto. O Termdock inverte isso. Ele mantém cada sessão aberta no servidor dele, sem prazo, até você encerrá-la. Os navegadores só se conectam e se desconectam, e quando você volta, do mesmo notebook, de outro computador ou do celular, o terminal está exatamente como você deixou.

Como funciona

Três ideias sustentam o projeto.

Um emulador de terminal mora no servidor
Para cada sessão, o Termdock mantém um emulador de referência alimentado com a saída SSH bruta. O navegador que se conecta recebe uma foto desse estado e depois a saída ao vivo, então desenha uma cópia exata, com tela alternativa e modos do terminal.
O tmux protege as sessões, e você nunca o vê
Cada sessão SSH roda dentro de um tmux só dela no servidor, controlado pelo modo de controle do tmux: sem barra de status, sem tecla de prefixo, com a rolagem normal. Depois de uma queda de rede ou de um reinício, o Termdock se reconecta e reconstrói a tela e o histórico. Servidores sem tmux também funcionam, marcados como sem proteção.
As sessões pertencem ao serviço, não ao navegador
O app web cuida de usuários, servidores, credenciais e layout; o gerenciador de sessões cuida das conexões, dos emuladores e da reconexão. Publicar uma versão nova do app web nunca derruba um terminal.

Onde ele se encaixa

Para quem mantém shells abertos em máquinas remotas e quer chegar a eles de qualquer lugar.

Um servidor de desenvolvimento ou uma VPS
Editores, builds, testes em modo watch e logs continuam rodando na máquina onde o código está, e você retoma tudo do notebook, de outro computador ou do celular.
Tarefas longas e agentes de código
Um deploy, uma migração, um processamento de dados ou um agente de IA trabalhando no terminal continua enquanto o notebook dorme. Acompanhe de qualquer navegador.
Um shell remoto no navegador
Um cliente SSH web auto-hospedado, e uma alternativa ao Apache Guacamole quando o que você precisa são terminais que continuam abertos: sem cliente SSH nem chave no aparelho que você estiver usando, com chaves do host verificadas e credenciais cifradas no seu servidor.
Plantão pelo celular
A lista de sessões, um terminal em tela cheia e uma barra de teclas com Esc, Ctrl, Alt, Tab e as setas.

Ele trabalha junto com as ferramentas que você já usa. O Termdock roda o tmux por você, de forma invisível, então você nunca mais digita tmux attach; o seu próprio tmux, o Zellij, o Herdr ou qualquer outro programa de terminal continua rodando dentro de uma sessão, mesmo depois que o navegador fecha.

O que você ganha

  • Sessões SSH persistentes, que sobrevivem a abas fechadas, redes instáveis e reinícios do serviço.
  • Proteção automática e invisível com tmux, detectada por servidor, com um aviso honesto quando falta.
  • Uma área de trabalho com lista de sessões, abas e painéis divididos, guardada no servidor e restaurada em qualquer navegador.
  • Um painel de arquivos ao lado de cada terminal: enviar, baixar, renomear, apagar e criar pastas, pela própria conexão SSH da sessão.
  • Dá para usar no celular, com layout responsivo e uma barra de teclas extras.
  • Vários usuários, isolados: cada um vê só os próprios servidores, credenciais e sessões.
  • Feito como um bastion: credenciais cifradas com uma chave que só o plano de dados tem, confiança explícita nas chaves do host, login em duas etapas e log de auditoria.
  • Chaves SSH, senhas e pedidos de 2FA, com os pedidos repassados ao seu navegador.
  • Inglês e português do Brasil.
  • Instalação com um comando, usando Docker Compose e Caddy, com HTTPS automático.

Rode o Termdock

Um comando sobe três contêineres atrás de uma origem só: o Caddy para o TLS, o app web e o gerenciador de sessões. Você precisa de Docker com Compose v2 num host Linux.

git clone https://github.com/ativaone/termdock.git termdock && cd termdock
deploy/scripts/init-secrets.sh                      # gera os segredos; faça backup de deploy/secrets/master_key
docker compose -f deploy/compose.yaml up -d --build # constrói as duas imagens e sobe tudo
docker compose -f deploy/compose.yaml logs web      # o token de uso único para criar o primeiro admin em /setup

Logo de saída ele atende em https://localhost, com um certificado da CA local do Caddy. O guia de instalação, em inglês, cobre domínio e TLS, proxy reverso, backups, atualizações e solução de problemas.

O Termdock está em pré-alfa

O runtime, a área de trabalho e a instalação com Docker funcionam de ponta a ponta e passaram por uma revisão de segurança interna, mas ainda não há release. Mantenha-o longe de servidores de produção até a v0.1.0.
